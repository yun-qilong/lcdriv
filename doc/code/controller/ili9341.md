# Controller\<ControllerType::ILI9341, M, N\> 算法文档（Spec）

> 本文是 Controller 层的算法规范。数据来源：ILI9341 数据手册 + 硬件验证过的常用初始化子集（SPI 接口、RGB565）。

## 1. 定位与职责

ILI9341 设备协议层，与 `Bus`、`PanelMgr` 同为 Driver 聚合的平行组件（架构 spec §2）。职责：命令集语义、DC 引脚控制、按 M/N 计算的窗口与帧长；总线类型经 duck-typing 解耦。初始化命令序列为装配期一次性行为，由装配方（Driver）触发（见 §5）；CS/RST 由 PanelMgr 管理（本类方法在 CS 有效下运行，§3）。无错误路径（假定硬件正常）。

## 2. 类签名与公开接口

```cpp
template <int M, int N>
class Controller<ControllerType::ILI9341, M, N> {
public:
    // 编译期常量：方向（MADCTL）按 M/N 推导（规则见 §4.2）
    static constexpr uint8_t kMadctlDefault = (M > N) ? 0x60 : 0x00;

    // 构造：注入 DC 引脚（GpioPin；低 = 命令态，高 = 数据态）
    Controller(GpioPin dc);

    template <typename B> void writeCommand(B& bus, uint8_t cmd);
    template <typename B> void writeData(B& bus, const uint8_t* data, uint16_t n);
    template <typename B> void pushFrame(B& bus, const uint8_t* px);
    template <typename B> void fillScreen(B& bus, uint16_t color);
    template <typename B> uint32_t readID(B& bus);
    template <typename B> void setOrientation(B& bus, uint8_t madctl);
};
```

- **命令码常量（public，协议数据，来源：ILI9341 手册 §8.3）**：`NOP=0x00`、`SWRESET=0x01`、`SLPOUT=0x11`、`GAMSET=0x26`、`DISPON=0x29`、`CASET=0x2A`、`PASET=0x2B`、`RAMWR=0x2C`、`TEON=0x35`、`MADCTL=0x36`、`COLMOD=0x3A`、`FRMCTR1=0xB1`、`DISCTRL=0xB6`、`PWCTR1=0xC0`、`PWCTR2=0xC1`、`VMCTR1=0xC5`、`VMCTR2=0xC7`、`RDID=0xD3`、`ENABLE3G=0xF2`。协议方法内部使用；公开供调用方核对/扩展。
- DC 引脚以库级公共 `GpioPin`（`GPIO_TypeDef* + pin`，见 架构 spec 公共类型）经构造注入。
- M/N = **逻辑分辨率** = 应用帧缓冲的列数/行数（编译期）。例：竖屏应用 240×320 → M=240、N=320；横屏应用 320×240 → M=320、N=240。
- B = duck-type：任意具备 `send(const uint8_t*, uint16_t)` / `sendBulk(const uint8_t*, uint32_t)` / `read(uint8_t*, uint16_t)` 的总线类型（本库为 `Bus<BusType::SPI, P, dma>`）。`pushFrame` 的像素段经 `sendBulk`，命令/参数/单色流经 `send`。
- 上电 = 装配方先执行硬件复位（时序见 PanelMgr spec）再执行初始化命令表（§6 #2..#15），均为装配期一次性行为。装配方见 Driver spec（LcdDriver 的两种初始化范式）。

## 3. 引脚与环境契约

| 项 | 约定 | 实测 |
|---|---|---|
| DC | 低电平 = 命令态，高电平 = 数据态 | 由使用方以 `GpioPin dc` 经构造注入 |
| CS | 本类不操作；所有方法前置 = CS 已有效（低） | 由 PanelMgr 管理（每屏独立，见 PanelMgr spec） |
| RST | 本类不操作；复位在装配期由 PanelMgr 执行 | 见 PanelMgr spec |
| 延时 | 毫秒级阻塞 `HAL_Delay`（数值见 §6） | — |
| 环境先决 | 使用方已完成 HAL GPIO/SPI 初始化（见 Bus spec §3）；本类不改总线配置 | — |

> `GPIO_TypeDef`/`SPI_HandleTypeDef` 为 STM32 HAL/CMSIS 类型（非本库定义；类型名在 STM32 全家族一致）。本类所在头**不 include 家族头**，依赖使用方 TU 先让 HAL 可见（include 顺序契约，见 Bus spec §3）。

**CS 事务契约**：本类所有方法都在"CS 已有效（低）"的前提下工作，返回时 CS 仍有效；选中与释放由 Driver 经 PanelMgr 在每次公开操作前后完成（Driver spec §4）。

## 4. 分辨率、方向与数据编码约定（本类所有窗口/像素行为的依据）

### 4.1 M/N = 逻辑分辨率（应用空间）

- M/N 由**应用决定**（与面板是否旋转无关）：M = 逻辑列数（宽）、N = 逻辑行数（高），等于应用帧缓冲尺寸。`pushFrame` 的帧长 `M*N*2` 与之严格对应。
- 面板物理尺寸（ILI9341 GRAM 为 240 列 × 320 行、竖屏原生）是本类内部常量，**仅用于方向推导**（4.2），不改变窗口/帧长的计算。
- 窗口（0x2A/0x2B）参数始终按**应用空间** M×N 计算；ILI9341 旋转模式下地址寄存器按应用空间解释（与主流旋转库一致）。

### 4.2 方向（MADCTL）由 M/N 编译期推导，无"固定默认"

- MADCTL 的取值是 (M, N) 相对面板方向的**编译期推导结果**。
- 推导前提：本规则以 **ILI9341 面板原生竖屏（GRAM 240 列 × 320 行）** 为前提；若未来引入原生横屏面板的控制器，其旋转推导另行定义（本规则不通用）。
- 推导规则（本实现）：
  - **逻辑竖屏**（M < N，如 240×320）：MADCTL = `0x00`（竖屏、RGB 顺序、无镜像）。
  - **逻辑横屏**（M > N，如 320×240）：MADCTL = 旋转（MV=0x20）+ 镜像位，当前取 `0x60`（MV|MX）。`0xA0`（MV|MY）与其画面互为上下翻转，最终取值以硬件实测为准。
  - **方屏（M == N）**：未定义使用——推导回退 `0x00`，且该分辨率不覆盖整块 GRAM（应用空间须与面板物理尺寸匹配，见 §4.1）；spec 不承诺方屏显示正确。
  - 颜色顺序：RGB（BGR=0）；若颜色通道互换则置 BGR=0x08。
- 运行时覆盖：`setOrientation(madctl)` 仍可写任意 MADCTL 值（调试用），但显示内容正确性由调用方负责。

### 4.3 窗口与像素编码

- **坐标系**：X = 列（0x2A），Y = 行（0x2B），均为应用空间。
- **窗口参数编码**：每个边界 2 字节、大端（高字节先发）。全屏窗口固定 XS=0、XE=M-1；YS=0、YE=N-1。
  - 竖屏 240×320：0x2A `[0x00 0x00 0x00 0xEF]`（XE=239=0x00EF）；0x2B `[0x00 0x00 0x01 0x3F]`（YE=319=0x013F）。
  - 横屏 320×240：0x2A `[0x00 0x00 0x01 0x3F]`（XE=319=0x013F）；0x2B `[0x00 0x00 0x00 0xEF]`（YE=239=0x00EF）。
- **像素格式**：RGB565，每像素 2 字节，**先高字节后低字节**（`0xF800` → 先 `0xF8` 后 `0x00`）。
- **帧长**：`M*N*2` 字节；240×320 与 320×240 均为 **153,600 字节**。

## 5. 公开函数规范

### 装配与上电（一次性契约，非公开入口）

- 装配方（Driver spec 的 LcdDriver）在其**构造（范式二）或 init（范式一）**中，对每块屏执行一次完整上电：硬件复位（PanelMgr spec `reset`）+ 初始化命令序列（§6 #2..#15），全程处于该屏的 CS 事务内（逐屏装配顺序见 Driver spec §5）。
- 本类不提供可反复调用的 `init` 入口；"重新上电" = 装配方再次构造/init（每次都是完整复位 + 序列，幂等）。
- 完成后：屏幕可显示；此后 §5 各协议函数才可调用。

### `template <typename B> void writeCommand(B& bus, uint8_t cmd)`

- **功能**：发送 1 字节命令。DC 置命令态（低），经 `bus.send` 发出 `cmd`。
- **前置**：已装配；CS 有效（事务内）。
- **后置**：控制器将该字节解析为命令。
- **副作用**：DC 低电平；总线发送 1 字节。

### `template <typename B> void writeData(B& bus, const uint8_t* data, uint16_t n)`

- **功能**：发送 `n` 字节数据（命令参数或像素）。DC 置数据态（高），经 `bus.send` 发出 `data[0..n-1]`。
- **边界**：`n` ≤ 65,535；**`n == 0` 时无任何总线操作、DC 电平不变**；调用方不应依赖 n==0 后 DC 的具体电平。
- **前置**：已装配；CS 有效；`data` 有效。
- **副作用**：DC 高电平；总线发送 `n` 字节。

### `template <typename B> void pushFrame(B& bus, const uint8_t* px)`

- **功能**：整帧推送，按 §4.3 编码。协议序列固定为：
  1. 0x2A：列窗口 XS=0、XE=M-1（4 字节大端）；
  2. 0x2B：行窗口 YS=0、YE=N-1（4 字节大端）；
  3. 0x2C（写显存）：DC 置数据态，紧接**一次 `bus.sendBulk(px, M*N*2)`** 连续发送像素数据。
- **发送粒度（固定契约，非实现自由）**：像素段为**一次 `sendBulk`**；≤65,535 的分块迁入 Bus 层（Bus spec §4），本类不再自行拆分。段内不得插入任何命令；CS 全程有效，释放由 Bus 在 sendBulk 完成点执行（Driver spec §4）。测试按"窗口 3 次 writeReg + 1 次 sendBulk"断言（见 测试框架 case design）。
- **前置**：已装配；`px` 指向 `M*N*2` 字节缓冲（调用方已按高字节在前组织，本类不做字节序转换；dma=true 时 `px` 须满足 Bus spec §3 帧缓冲前置）。
- **后置**：屏幕显示 `px`（dma=true 时在传输完成后异步生效）。
- **终止语义**：0x2C 数据流在 CS 拉高（事务结束）时终止；未发完的像素不写入。
- **边界**：窗口必须先设对再流像素，否则错位/滚动（由本函数顺序保证）。

### `template <typename B> void fillScreen(B& bus, uint16_t color)`

- **功能**：整屏填充单色。协议：0x2A 全屏列窗口 → 0x2B 全屏行窗口 → 0x2C → 连续发送 `M*N*2` 字节（`color` 高字节/低字节的重复模式，每像素 2 字节）。
- **缓冲与展开（固定粒度，非实现自由）**：调用方**无需**提供缓冲——颜色重复模式由本类**逐行展开**：每行 `2*M` 字节一次 `bus.send`，共 `N` 次（240×320 → 320 次 × 480 字节；320×240 → 240 次 × 640 字节；单次均 ≤ 65,535）。测试按此粒度断言。
- **前置**：已装配；CS 有效。
- **后置**：所有像素变为 `color`。

### `template <typename B> uint32_t readID(B& bus)`

- **功能**：读取芯片 ID（验证接线/型号）。**固定协议**：DC 命令态发 0xD3 → DC 数据态读回 **4 字节** `[b0 b1 b2 b3]` → **丢弃首字节 b0（哑字节）** → 返回 `(b1<<16) | (b2<<8) | b3`。
- **期望值**：ILI9341 返回字节序为 `0x93`（厂商）`0x41`（驱动）`0x??`（模块）→ 返回值 `0x9341??`（实测模块字节 0x00 → `0x934100`）。
- **校验归属**：本类**不**校验期望值；`0x93/0x41` 比对由调用方完成。
- **前置**：已装配；MISO 已接（`bus` 需支持 `read`）；CS 有效。
- **副作用**：总线发送 1 字节 + 读回 4 字节。

### `template <typename B> void setOrientation(B& bus, uint8_t madctl)`

- **功能**：写 0x36（MADCTL）为 `madctl`（1 字节数据）。位义（按手册）：bit6 MV（横/竖）、bit5 MX / bit4 MY（镜像）、bit3 BGR（颜色顺序）。
- **后置**：后续窗口/推帧的物理扫描方向与颜色顺序改变。
- **注意**：本类不换算宽高——方向改变后窗口仍为应用空间 (0,0)-(M-1,N-1)，画面按新方向旋转；横竖屏与分辨率匹配属调用方职责。正常使用不调用本函数（方向已由 4.2 编译期定）；本函数为调试/运行时覆盖入口。

## 7. 事务与总线边界（跨层约束）

- 单次 `bus.send` / `bus.read` 长度上限 65,535 字节（uint16_t）；整段像素经 `bus.sendBulk(px, M*N*2)`（uint32_t，内部 ≤65,535 分块迁入 Bus，见 Bus spec §4）。
- 发送拆分粒度是**固定契约**（见 §5：pushFrame 像素流 = 一次 sendBulk；fillScreen 单色流按行展开），非实现自由——测试按该粒度断言，改动须同步 §5 与对应 case design。
- 本类方法全部运行在 Driver 的单个 CS 事务内（见 Driver spec §4）；本类内部不得自行拉高/拉低 CS（pushFrame 的 CS 释放由 Bus 在 sendBulk 完成点执行）。

## 8. 当前限制

- 无背光（BL）控制——面板背光外部常亮；BL 预留，归属未定义（见架构 spec §2）。
- 无错误路径（假定硬件正常；唯一自检手段是 `readID` 由调用方比对）。
- 横屏（M > N）MADCTL 当前取 0x60，最终取值以硬件实测为准（见 §4.2）。

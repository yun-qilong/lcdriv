# Controller\<ControllerType::ILI9341, M, N\> 算法文档（Spec）

> **状态：可约束实现。** 本文是 Controller 层的算法规范（非介绍）。数据来源：raycaster-demo 实测驱动 `stm32/led_blink/Core/Src/ili9341.c`（已硬件验证点亮 + 读 ID）与 ILI9341 数据手册；与实测冲突时以实测为准，修订记录见文末。

## 1. 定位与职责

ILI9341 设备协议层。职责：命令集语义、DC/RST 引脚控制、与模板参数 M/N 相关的窗口与帧长。**不**持有/操作 CS（归 Driver），**不**关心总线具体类型（duck-typing），**不**含错误路径（阶段一假定硬件正常）。本类**不暴露独立的生命周期/初始化入口**——上电序列是本类装配期的一次性行为，由装配方（LcdDriver）触发（见 §5 装配与上电）。

## 2. 类签名与公开接口

```cpp
template <int M, int N>
class Controller<ControllerType::ILI9341, M, N> {
public:
    // 构造：注入 DC / RST 引脚（GPIO，均为低有效控制）
    Controller(GPIO_TypeDef* dc_port, uint16_t dc_pin,
               GPIO_TypeDef* rst_port, uint16_t rst_pin);

    template <typename B> void writeCommand(B& bus, uint8_t cmd);
    template <typename B> void writeData(B& bus, const uint8_t* data, uint16_t n);
    template <typename B> void pushFrame(B& bus, const uint8_t* px);
    template <typename B> void fillScreen(B& bus, uint16_t color);
    template <typename B> uint32_t readID(B& bus);
    template <typename B> void setOrientation(B& bus, uint8_t madctl);
};
```

- M/N = **逻辑分辨率** = 应用帧缓冲的列数/行数（编译期）。例：竖屏应用 240×320 → M=240、N=320；横屏应用 320×240 → M=320、N=240。
- B = duck-type：任意具备 `send(const uint8_t*, uint16_t)` / `read(uint8_t*, uint16_t)` 的总线类型（本库为 `Bus<BusType::SPI>`）。
- 上电序列（复位 + 命令表，§6）在本类的装配期执行；装配方见 doc/04（LcdDriver 的两种初始化范式）。

## 3. 引脚与环境契约

| 项 | 约定 | 实测 |
|---|---|---|
| DC | 低电平 = 命令态，高电平 = 数据态 | PB0 |
| RST | 低电平复位；拉高后需延时 | PB1 |
| CS | 本类不操作；所有方法前置 = 调用方已拉低 CS | — |
| 延时 | 毫秒级阻塞 `HAL_Delay`（数值见 §6） | — |
| 环境先决 | CubeMX 已完成 GPIO 与 SPI1 初始化（见 doc/02 §3）；本类不改总线配置 | — |

> `GPIO_TypeDef`/`SPI_HandleTypeDef` 为 STM32 HAL/CMSIS 类型（非本库定义；类型名在 STM32 全家族一致）。本类所在头**不 include 家族头**，依赖使用方 TU 先让 HAL 可见（include 顺序契约，见 doc/02 §3）。

**CS 事务契约**：本类所有方法都在"CS 已有效（低）"的前提下工作，返回时 CS 仍有效；CS 的拉低/拉高由 Driver 在每次公开操作前后完成（doc/04 §4）。

## 4. 分辨率、方向与数据编码约定（本类所有窗口/像素行为的依据）

### 4.1 M/N = 逻辑分辨率（应用空间）

- M/N 由**应用决定**（与面板是否旋转无关）：M = 逻辑列数（宽）、N = 逻辑行数（高），等于应用帧缓冲尺寸。`pushFrame` 的帧长 `M*N*2` 与之严格对应。
- 面板物理尺寸（ILI9341 GRAM 为 240 列 × 320 行、竖屏原生）是本类内部常量，**仅用于方向推导**（4.2），不改变窗口/帧长的计算。
- 窗口（0x2A/0x2B）参数始终按**应用空间** M×N 计算；ILI9341 旋转模式下地址寄存器按应用空间解释（与主流旋转库一致）。

### 4.2 方向（MADCTL）由 M/N 编译期推导，无"固定默认"

- MADCTL 的取值不是常量，而是 (M, N) 相对面板方向的**编译期推导结果**（同一偏特化实现内的 `if constexpr`；分辨率维度仍不特化）。
- 推导规则（本实现）：
  - **逻辑竖屏**（M < N，如 240×320）：MADCTL = `0x00`（竖屏、RGB 顺序、无镜像）——**实测有效**。
  - **逻辑横屏**（M > N，如 320×240，**当前项目目标**）：MADCTL = 旋转（MV=0x20）+ 镜像位。候选值 `0x60`（MV|MX）或 `0xA0`（MV|MY），二者画面互为上下翻转——**具体取值待硬件实测锁定**（方法：推横屏测试图；若上下颠倒换另一候选值；锁值后登记入文末修订记录并固化到推导）。
  - 颜色顺序：默认 RGB（BGR=0，实测验证）；若实测颜色通道互换再置 BGR=0x08。
- 运行时覆盖：`setOrientation(madctl)` 仍可写任意 MADCTL 值（调试用），但显示内容正确性由调用方负责。

### 4.3 窗口与像素编码

- **坐标系**：X = 列（0x2A），Y = 行（0x2B），均为应用空间。
- **窗口参数编码**：每个边界 2 字节、大端（高字节先发）。全屏窗口固定 XS=0、XE=M-1；YS=0、YE=N-1。
  - 竖屏 240×320：0x2A `[0x00 0x00 0x00 0xEF]`（XE=239=0x00EF）；0x2B `[0x00 0x00 0x01 0x3F]`（YE=319=0x013F）。
  - 横屏 320×240：0x2A `[0x00 0x00 0x01 0x3F]`（XE=319=0x013F）；0x2B `[0x00 0x00 0x00 0xEF]`（YE=239=0x00EF）。
- **像素格式**：RGB565，每像素 2 字节，**先高字节后低字节**（`0xF800` → 先 `0xF8` 后 `0x00`）。
- **帧长**：`M*N*2` 字节；240×320 与 320×240 均为 **153,600 字节**。

## 5. 公开函数规范

### 装配与上电（一次性契约，非公开入口）

- 装配方（doc/04 的 LcdDriver）在其**构造（范式二）或 init（范式一）**中执行一次：RST 复位时序 + §6 命令序列（全程处于该次装配的 CS 事务内）。
- 本类不提供可反复调用的 `init` 入口；"重新上电" = 装配方再次构造/init（每次都是完整复位 + 序列，幂等）。
- 完成后：屏幕可显示；此后 §5 各协议函数才可调用。

### `template <typename B> void writeCommand(B& bus, uint8_t cmd)`

- **功能**：发送 1 字节命令。DC 置命令态（低），经 `bus.send` 发出 `cmd`。
- **前置**：已装配；CS 有效（事务内）。
- **后置**：控制器将该字节解析为命令。
- **副作用**：DC 低电平；总线发送 1 字节。

### `template <typename B> void writeData(B& bus, const uint8_t* data, uint16_t n)`

- **功能**：发送 `n` 字节数据（命令参数或像素）。DC 置数据态（高），经 `bus.send` 发出 `data[0..n-1]`。
- **边界**：`n` ≤ 65,535；**`n == 0` 时无任何总线操作、DC 保持命令态**。
- **前置**：已装配；CS 有效；`data` 有效。
- **副作用**：DC 高电平；总线发送 `n` 字节。

### `template <typename B> void pushFrame(B& bus, const uint8_t* px)`

- **功能**：整帧推送，按 §4.3 编码。协议序列固定为 3 段：
  1. 0x2A：列窗口 XS=0、XE=M-1（4 字节大端）；
  2. 0x2B：行窗口 YS=0、YE=N-1（4 字节大端）；
  3. 0x2C（写显存）：紧接连续发送 `M*N*2` 字节像素数据。
- **分块约束**：像素段总长 153,600 字节 > 总线单次上限 65,535 ⇒ **必须拆分为多次连续 `bus.send`（每次 ≤ 65,535）**，段内不得插入任何命令；CS 全程有效（由 Driver 保证）。
- **前置**：已装配；`px` 指向 `M*N*2` 字节缓冲（调用方已按高字节在前组织，本类不做字节序转换）。
- **后置**：屏幕显示 `px`。
- **终止语义**：0x2C 数据流在 CS 拉高（事务结束）时终止；未发完的像素不写入。
- **边界**：窗口必须先设对再流像素，否则错位/滚动（由本函数顺序保证）。

### `template <typename B> void fillScreen(B& bus, uint16_t color)`

- **功能**：整屏填充单色。协议：0x2A 全屏列窗口 → 0x2B 全屏行窗口 → 0x2C → 连续发送 `M*N*2` 字节（`color` 高字节/低字节的重复模式，每像素 2 字节）。
- **缓冲**：调用方**无需**提供缓冲（重复模式可由本类逐行展开，展开粒度属实现自由，单次传输仍 ≤ 65,535）。
- **前置**：已装配；CS 有效。
- **后置**：所有像素变为 `color`。

### `template <typename B> uint32_t readID(B& bus)`

- **功能**：读取芯片 ID（验证接线/型号）。**固定协议**：DC 命令态发 0xD3 → DC 数据态读回 **4 字节** `[b0 b1 b2 b3]` → **丢弃首字节 b0（哑字节）** → 返回 `(b1<<16) | (b2<<8) | b3`。
- **期望值**：ILI9341 返回字节序为 `0x93`（厂商）`0x41`（驱动）`0x??`（模块）→ 返回值 `0x9341??`（实测模块字节 0x00 → `0x934100`）。
- **校验归属**：本类**不**校验期望值；`0x93/0x41` 比对由调用方完成。
- **前置**：已装配；MISO 已接（`bus` 需支持 `read`）；CS 有效。
- **副作用**：总线发送 1 字节 + 读回 4 字节。

### `template <typename B> void setOrientation(B& bus, uint8_t madctl)`

- **功能**：写 0x36（MADCTL）为 `madctl`（1 字节数据）。位义（按手册）：bit6 MV（横/竖）、bit5 MX / bit4 MY（镜像）、bit3 BGR（颜色顺序）。
- **后置**：后续窗口/推帧的物理扫描方向与颜色顺序改变。
- **注意**：本类不换算宽高——方向改变后窗口仍为应用空间 (0,0)-(M-1,N-1)，画面按新方向旋转；横竖屏与分辨率匹配属调用方职责。正常使用不调用本函数（方向已由 4.2 编译期定）；本函数为调试/运行时覆盖入口。

## 7. 事务与总线边界（跨层约束）

- 单次 `bus.send` / `bus.read` 长度上限 65,535 字节（uint16_t）；超过必须拆分（拆分数由实现决定，只约束"单次 ≤ 65,535 且连续"）。
- 本类方法全部运行在 Driver 的单个 CS 事务内（见 doc/04 §4）；本类内部不得自行拉高/拉低 CS。

## 8. 当前限制 / 修订记录

- 本实现无背光（BL）控制——面板背光外部常亮；预留日后归本类。
- 错误路径：无（阶段一假定硬件正常；唯一自检手段是 `readID` 由调用方比对）。
- **修订记录**：
  1. readID：改为"0xD3 后读 4 字节、丢首哑字节"（原稿写 3 字节，与实测不符）。
  2. 初始化序列：替换为本板实测子集（原稿为 Adafruit 全量命令与伽马表，非本实现所用）。
  3. 新增 §4 编码约定与 §7 分块约束（原稿缺失）。
  4. **方向策略（本版）**：删除"MADCTL=0x00 固定默认"的表述；M/N 明确为**逻辑分辨率**，MADCTL 由 M/N 编译期推导（§4.2）。横屏 MADCTL 候选值（0x60/0xA0）**待硬件实测锁定**——锁定后在本条登记并固化。
  5. **初始化范式（本版）**：移除 Controller 的公开 `init(B& bus)` 入口；上电序列改为"装配期一次性契约"（§5），由 LcdDriver 的构造（范式二）/init（范式一）触发（见 doc/04 §3）。
